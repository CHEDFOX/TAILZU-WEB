# x0bot.com — architecture

## Working rules (every change, every session)

- **Read `WORKING-ON.md` first.** It says what other sessions are building right now and which files they hold. Add your own
  item when you start something big, keep off files another item holds, and remove your item when it lands.
- **Build the renderer way.** Anything the apps draw is built as server data: read `TAILZU-BACKEND/docs/renderer.md`.
- **Branch.** Work on `main` in all four repos (TAILZU-BACKEND, TAILZU-FRONTEND, TAILZU-DESKTOP, TAILZU-WEB), starting from the latest
  `main`. No pull requests unless the owner asks.
- **Organising.** One feature or component per file, in folders by area; no catch-all files. Adding, moving or removing a file means
  updating this archi.md. Each feature has its doc in `docs/<feature>.md`, updated with the feature. Delete dead code you touch or
  replace: no unused files, exports or commented-out code.
- **Server first.** Screens and logic go on the server (TAILZU-BACKEND, server-driven screens) when they can, so no app release is
  needed. Render new screens (`tulmi/scripts/bots-render`) and look at them.
- **Data.** A new table needs the next numbered migration in `tulmi/supabase/migrations`; tell the owner which one to run.
- **Commits.** Author `CHEDFOX <madefox6666@gmail.com>`, with no trailers (no co-author or session lines). Commits, code, comments and
  docs read as written by the author: never a word about the tool that helped write them, no "generated by" lines. Plain, human language.
- **Committing.** Only the files you changed, by path (`git add <paths>`, `git commit -- <paths>`). Never `git add -A`, never force-push.
  Run the typecheck and the full tests first. Here: `node csp.mjs` after any edit to an inline `<script>` or `<style>` in index.html.
- **Secrets.** Never print, log or commit a key, and never ask the owner to paste one: secrets live only in the server's `.env`. Don't
  search the machine for credentials.
- **Deploys.** Don't ssh or deploy; give the owner the command: `ssh root@91.108.104.168 "cd ~/tulmi && ./deploy/ship.sh"` (server),
  `ssh root@91.108.104.168 "cd ~/tulmi && ./deploy/cloudflare.sh"` (Xode's jobs on Cloudflare). This site deploys itself from `main` (to the VPS, `deploy/ship.sh`).
- **Replies.** Short and simple, with commands to copy and paste.

The public site for X0 Bot. One static page and a set of
rewrites that put the backend's pages (pricing, privacy, downloads, SEO pages) under the same domain. No build
step, no framework, no dependencies. Served by nginx on the VPS, deployed on every push to `main`.

## Layout

```
index.html              the page: markup for the film, the views and the bands, the tag manager inline, a <noscript> fallback; loads js/main.js
js/                     the page's script, one ES module per part (no build step; the CSP allows scripts from this origin)
  main.js               the opening film ("hey X0", the reply, the face), the work view's three stories, its finale and the line beside it,
                        and the six cases' grid (hover or click to enlarge); `sayer` swaps the work view's line; imports stage.js first
  stage.js              the fabric's frame loop and resize, the pointer and the scroll on the water (`scroll.quiet` while the page
                        scrolls itself), the key's per-device target and its lean
  minis.js              the small bots: a jetpack Blip over the film, a skateboarding one on the work view's boxes, one
                        peeking from behind the cases; one canvas over the page, only the view most on screen runs
  blip/blip.js          Blip's renderer, copied unchanged from TAILZU-DESKTOP src/shared/blip.js
  blip/moves.js         GENERATED by scripts/gen-blip-moves.mjs: his card poses and a few gestures, sampled from the app's catalog
  blip/kit.js           blip(): the renderer with those moves put back into its tables (the minis, and the food story's Blip)
  util.js               small helpers, and the window's size and pixel ratio (`view`)
  paper/grain.js        the paper's grain and light
  paper/water.js        the plane as water: a 2-D wave equation, splash() and sample()
  paper/words.js        the plane of tiny words in the world's scripts, moved by the water; their 0/1 flicker
  paper/glitch.js       the page's own words flicker into 0/1 under the pointer (not inside `[data-noglitch]`, i.e. the film's card)
css/site.css            the whole page's look: the card, the showcases (box and line), the devices and every screen in them, the six cases, the bands
media/meet/             three muted five-second clips of people on a video call, for the meeting card (Mixkit, free stock video)
api/                    the serverless functions Vercel ran (unused on the VPS: the API serves both routes; to delete once the move is settled)
  _meta.js              shared Meta pixel / Conversions API helpers (reads the dataset id and token from Vercel env)
  site-event.js         POST /v1/site/event: a page event (e.g. a download press) sent to Meta's Conversions API
  site-events.js        GET /site-events.js: the pixel loader script
vercel.json             redirects (tailzu.space → x0bot.com), rewrites to the API, security headers, the page's CSP, caching
csp.mjs                 writes the hashes of index.html's inline blocks into vercel.json's CSP, then remakes deploy/nginx/ (`node csp.mjs`, `--check`)
deploy/
  nginx.mjs             vercel.json → nginx config (`node deploy/nginx.mjs`, `--check`); fails on anything it cannot translate
  nginx/x0bot.conf      the config the VPS runs (TLS); x0bot.http.conf is the plain-HTTP one used until the certificate exists
  ship.sh               on the VPS: pull main, new release, switch, install the nginx config only if nginx accepts it; ROLLBACK=1
  check.sh              asks the live site (or `--ip` the VPS) every route, header and redirect, and what must never be served
.github/workflows/deploy.yml  on push to main: the two --checks, then ssh with a key that can run only ship.sh
robots.txt              crawler rules (search engines and answer engines allowed by name)
<key>.txt               the IndexNow key file
og.png                  the link-preview image
favicon.*, apple-touch-icon.png, icon-*.png, site.webmanifest
                        the app icon in every size browsers and phones ask for (kept at the root, where they look)
README.md               how the page behaves, what to run after a change, how publishing works
.vercelignore           files kept off the deployed site (README.md, archi.md, csp.mjs)
```

## How it fits together

- The browser loads `index.html`; `js/main.js` imports `js/stage.js`, which starts the fabric (grain, water, words, glitch)
  and its one frame loop, then plays the film in the white card, scrolls once to the work view, plays its three stories when
  it comes into sight, and plays the six cases together in their grid. The rest is an ordinary page.
- Everything dynamic belongs to the backend: nginx (from `vercel.json`'s rewrites) sends `/v1/...`, `/download`, the installers and the
  backend's pages to `api.x0bot.com`, so the site never handles accounts, payments or large files itself.
- Meta's pixel and its Conversions API copy are the backend's too (`META_PIXEL_ID`, `META_CAPI_TOKEN` in its `.env`).

## Working on it

- After editing an inline `<script>` or `<style>` in `index.html`: `node csp.mjs` (a stale hash blanks the page). The files in
  `js/` need no hash.
- After the backend's head changed: from `TAILZU-BACKEND/tulmi`, `npx tsx scripts/sync-site.mts ../../TAILZU-WEB/index.html`
  (add `--check` before pushing).
- After editing `vercel.json`: `node deploy/nginx.mjs` (csp.mjs runs it too); CI refuses a stale `deploy/nginx/`.
- Publishing: push to `main`; GitHub ships it to the VPS in under a minute. Check with `deploy/check.sh`.
