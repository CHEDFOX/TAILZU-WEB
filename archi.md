# x0bot.com — architecture

## Working rules (every change, every session)

- **Branch.** Work on `main` in all four repos (TAILZU-BACKEND, TAILZU-FRONTEND, TAILZU-DESKTOP, TAILZU-WEB), starting from the latest
  `main`. No pull requests unless the owner asks.
- **Organising.** One feature or component per file, in folders by area; no catch-all files. Adding, moving or removing a file means
  updating this archi.md. Each feature has its doc in `docs/<feature>.md`, updated with the feature. Delete dead code you touch or
  replace: no unused files, exports or commented-out code.
- **Server first.** Screens and logic go on the server (TAILZU-BACKEND, server-driven screens) when they can, so no app release is
  needed. Render new screens (`tulmi/scripts/bots-render`) and look at them.
- **Data.** A new table needs the next numbered migration in `tulmi/supabase/migrations`; tell the owner which one to run.
- **Commits.** Author `CHEDFOX <madefox6666@gmail.com>`, with no trailers (no co-author or session lines). Commits, code, comments and
  docs read as written by the author: never a word about the tool that helped write them, no "generated by" lines. Plain, human language.
- **Committing.** Only the files you changed, by path (`git add <paths>`, `git commit -- <paths>`). Never `git add -A`, never force-push.
  Run the typecheck and the full tests first. Here: `node csp.mjs` after any edit to an inline `<script>` or `<style>` in index.html.
- **Secrets.** Never print, log or commit a key, and never ask the owner to paste one: secrets live only in the server's `.env`. Don't
  search the machine for credentials.
- **Deploys.** Don't ssh or deploy; give the owner the command: `ssh root@91.108.104.168 "cd ~/tulmi && ./deploy/ship.sh"` (server),
  `ssh root@91.108.104.168 "cd ~/tulmi && ./deploy/cloudflare.sh"` (Xode's jobs on Cloudflare). This site deploys itself from `main`.
- **Replies.** Short and simple, with commands to copy and paste.

The public site for X0 Bot. One static page, three small serverless functions, and a set of
rewrites that put the backend's pages (pricing, privacy, downloads, SEO pages) under the same domain. No build
step, no framework, no dependencies. Deployed by Vercel on every push to `main`.

## Layout

```
index.html              the page: markup, one <style>, the tag manager inline, a <noscript> fallback; loads js/main.js
js/                     the page's script, one ES module per part (no build step; the CSP allows scripts from this origin)
  main.js               wires the parts together: sizes, the one frame loop, resize
  util.js               small helpers, and the window's size and pixel ratio (`view`)
  paper/grain.js        the paper's grain and light
  paper/water.js        the plane as water: a 2-D wave equation, splash() and sample()
  paper/words.js        the plane of tiny words in the world's scripts, moved by the water; their 0/1 flicker
  paper/glitch.js       the page's own words flicker into 0/1 under the pointer
  blip/figure.js        Blip's figure, drawn in greys (pose in, hand and antenna ball out)
  blip/dots.js          the one renderer that turns the figure into his ink sticker and dots
  blip/walker.js        his bouncy walk (any scene: its height, ground, speed and water)
  blip/antenna.js       into his antenna and back out: every dot of him a particle on springs; the antenna a springy stalk with a glowing ball
  page/opening.js       the opening: he walks in from the right and waves, then watches the pointer; hands him to the antenna and back
  page/key.js           the "Take me home" key and the name, arriving after the wave
  page/steps.js         the page never scrolls: a scroll, swipe or key moves it one step (0 opening, 1 into the antenna + screens, 2 out again)
  page/screens.js       the phone and the laptop either side of him (above and below on a tall window), on springs
  page/welcome.js       the app's first screen in them: the app's own render, and the phone's status bar
css/screens.css         the devices' frames and the screen in them
media/                  welcome-phone.webp, welcome-desk.webp: the Bots app's Welcome, from its renderers (button, link and the window's bots list painted out)
api/                    Vercel serverless functions (Node)
  _meta.js              shared Meta pixel / Conversions API helpers (reads the dataset id and token from Vercel env)
  site-event.js         POST /v1/site/event: a page event (e.g. a download press) sent to Meta's Conversions API
  site-events.js        GET /site-events.js: the pixel loader script
vercel.json             redirects (tailzu.space → x0bot.com), rewrites to the API, security headers, the page's CSP, caching
csp.mjs                 writes the hashes of index.html's inline blocks into vercel.json's CSP (`node csp.mjs`, `--check`)
robots.txt              crawler rules (search engines and answer engines allowed by name)
<key>.txt               the IndexNow key file
og.png                  the link-preview image
favicon.*, apple-touch-icon.png, icon-*.png, site.webmanifest
                        the app icon in every size browsers and phones ask for (kept at the root, where they look)
README.md               how the page behaves, what to run after a change, how publishing works
.vercelignore           files kept off the deployed site (README.md, archi.md, csp.mjs)
```

## How it fits together

- The browser loads `index.html`; `js/main.js` runs one frame loop for every part: the plane of words, the bot walking in
  and waving, the "Take me home" key and the name; then, step by step as the visitor scrolls, Blip into his antenna and the
  phone and the laptop with the app's Welcome, then Blip back out.
- Everything dynamic belongs to the backend: Vercel rewrites `/v1/...`, `/download`, the installers and the
  backend's pages to `api.x0bot.com`, so the site never handles accounts, payments or large files itself.
- Only the page's own analytics run here (`api/`), with credentials from Vercel's environment variables.

## Working on it

- After editing an inline `<script>` or `<style>` in `index.html`: `node csp.mjs` (a stale hash blanks the page). The files in
  `js/` need no hash.
- After the backend's head changed: from `TAILZU-BACKEND/tulmi`, `npx tsx scripts/sync-site.mts ../../TAILZU-WEB/index.html`
  (add `--check` before pushing).
- Publishing: push to `main`; Vercel deploys in under a minute.
